# horizon-site: playhorizon.dev

The website of Horizon (Minecraft: Java Edition 26.3 rewritten in Rust). Private. The game, the launcher and their
developer docs are in [ludovic111/horizon](https://github.com/ludovic111/horizon) (public), called "the game's
repository" below. People edit it too (not only agents): [README.md](README.md) has "Working on it", the layout, the docs
rules and the benchmarks; this page is the short map for agents.

## Build and test

```sh
node build.mjs && node serve.mjs              # dist/, served on http://localhost:4173
node --test src/ scripts/                     # all tests (npm test); no npm install needed
HORIZON_CHECKOUT=~/code/horizon node build.mjs   # read the game's files from a local checkout instead of GitHub
```

`build.mjs` has no dependencies and fails on a broken docs link, a missing image or a README without its parity
table. `npm install` only for `npm run assets` (fonts, screenshots, pixel art from the game's repository) and
`npm run shots` (Playwright screenshots at every width).

## Where the data comes from

- **The game's `main` on GitHub**, all files from one commit (`horizonRef` in build.mjs): `README.md` (parity
  table, harness count), `launcher/links.json` (Discord, Sponsor), `docs/api/*.md` (the `/docs/api` pages),
  `crates/horizon-theme/tokens.css` (design tokens, generated by `cargo run -p xtask -- tokens` there),
  `roadmap/roadmap.json` (the hub, and `/data/roadmap.json`, which Kira reads; generated by `tools/roadmap.py build`
  there). Change those in the game's repository, never here.
- **GitHub's API at build time**: releases, contributors, the roadmap's issues and pull requests.
- **Other services**: the mod registry's index (ludovic111/horizon-mods), Kira's contributors list, the telemetry
  server (players' benchmarks, the hub's forms; `telemetry.playhorizon.dev`).
- **This repository**: the pages (`src/`), the player docs (`docs/`), our benchmark runs (`data/benchmarks/`,
  `public/benchmarks.json`), assets (`public/`).

## Content-Security-Policy

`Caddyfile` serves a strict CSP. Inline `<script>`/`<style>` blocks are allowed by the hashes the build writes
(`.csp-script`, `.csp-style`); inline handlers, `style="…"` attributes and `javascript:` URLs are blocked. A new
origin (fetch, image, font) needs an entry in the Caddyfile's CSP, and third-party scripts, fonts and trackers are not
allowed at all.

## Deploy

Railway project `horizon-site`, service `site`, environment `production`: every push to `main` here goes live within
minutes (Dockerfile: Node builds, Caddy serves). When the files above change on the game's `main`, the site is
redeployed from source: for now by `~/code/horizon-parity/tools/site_redeploy_watch.sh` on the Mac mini (every 10
minutes), later by the game repository's `site-redeploy.yml` workflow. A failed build keeps the previous deployment live. After a deploy, check
https://playhorizon.dev (/, /hub, /mods, /docs/, /releases, /benchmarks, /data/roadmap.json).

## Rules

- Branch work in a worktree under `.claude/worktrees/<name>`; keep the main checkout on `main`.
- The site's rules (disclaimer, no Minecraft logo, no trackers, reduced motion): README "Rules the site keeps".
- Agents' PRs start with `> 🤖 Opened by Ludovic's AI agent (Claude), not by Ludovic himself.`, comments with
  `🤖 Agent:`; commits end with a `Co-Authored-By:` line for the agent.
- Never commit Mojang's files, secrets, or `dist/` and `shots/`.
